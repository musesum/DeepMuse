Ported four WinSky CA rules to Metal compute kernels under
`/Users/warren/Dev/Deep/Deep/Muse/Metal/`. All four compile standalone with
`xcrun -sdk iphoneos metal -c`. Source of truth: `WinSky/pixel/Rule.cpp`
(strictly read-only). Binding constraints from `Port/CallTree.md §4` applied.

| kernel file | kernel symbol |
|---|---|
| `cell.rule.drift.metal`  | `driftKernel`  |
| `cell.rule.happy.metal`  | `happyKernel`  |
| `cell.rule.warren.metal` | `warrenKernel` |
| `cell.rule.noise.metal`  | `noiseKernel`  |

Convention verified against `cell.rule.fred.metal` / `ave` / `slide`:
texture(0)=read input, texture(1)=write output, buffer(0)=`constant float& version`,
`uint2 gid [[thread_position_in_grid]]`, `bgra8Unorm`, toroidal `ew/ns/nwsw/nese`
macro block. State packing `.b`=cell value, `.g`=255−value, `(.a<<8)+.r`=HiC —
matching WinSky NextR (`r1→.b`, `r2→.g`, `r3→HiC`). These four use the ×255/÷255
scaling of `ave`/`slide` (with `+0.5` read rounding), not `fred`'s ×256.

## 1. Buffer bindings — NO extra buffers declared

Every kernel binds ONLY `buffer(0) version`, exactly what CellNode binds today.
No kernel declares `buffer(1)+`, so there is **no runtime hazard** and **no
required CellNode binding extension** for these four to run (contrast the `melt`
precedent, which declares an unbound `buffer(1) bits`).

`version` is repurposed per rule where the source has no version variants:

| kernel | buffer(0) `version` carries | why |
|---|---|---|
| drift  | `driftBits` (1..2)     | drift has no version variants; only knob is driftBits |
| happy  | `happyVersion` (2..3)  | genuine variant selector |
| warren | `warrenVersion` (0..1) | genuine variant selector (v0 omitted; 0→v1 fallback) |
| noise  | `noiseBits` (1..8)     | noise has no version variants; only knob is noiseBits |

## 3. Required CellNode binding extensions

**None required.** All four run on the existing single-buffer CellNode path.

### Recommended (OPTIONAL) extension — frame/time uniform for animation

`drift` (bits 2) and especially `noise` need per-frame variation to animate.
No frame/time uniform is bound today (`Stubs.md` gap #5: `CellNode.frame` exists
but is never bound). Consequently:

- **drift**: the ~50% tested-cell mask (bits 2) is STATIC per frame — a fixed
  spatial subset, not re-randomised each frame. (bits 1 tests every cell, so it
  is unaffected.)
- **noise**: fire mask AND random byte are hashed from (gid, version) only →
  the same cells fire to the same value every frame → **does not animate**. This
  is the single biggest divergence in the batch.

Fix (deferred, not implemented — would be a true binding extension, and an
unbound declared buffer is a runtime hazard):

1. Bind `CellNode.frame` (or a wall clock) to `buffer(1)` in
   `CellNode.computeShader` (`Mu/MuVision/.../Pipeline/CellNode.swift`).
2. Add `constant float& frame [[buffer(1)]]` to `driftKernel` and `noiseKernel`
   and fold `frame` into the hash seed.

Until CellNode binds buffer(1), do NOT declare it in the kernels (melt precedent).

## 4. Omitted variants

| rule | omitted | reason | to port later |
|---|---|---|---|
| happy  | **v1** | `Rule::swap` (Rule.cpp:681-701) is in-place, order-dependent, non-local (arbitrary (dx,dy) exchange with per-pass `\|0x10000` "claimed" bit). Not expressible as one gather pass. Also zeroes bits 8-31 (`*next=llc`). Shipped tree range (2..3) never selects it. | atomic compare-and-swap scatter kernel, or a multi-pass stochastic sorting network; write `.g/.r/.a=0` to match `*next=llc`. |
| warren | **v0** | two-pass: pass 1 mutates `*prev` in place (row-order-dependent, nw/ne overwritten, sw/se not), then re-syncs, pass 2 gathers pass-1 high words. Single dispatch with read/write aliased to one texture is non-deterministic on GPU. | two kernel dispatches with an explicit **intermediate texture** (pass-1 priority field written to a separate texture, pass 2 gathers from that stable snapshot). CellNode's single-dispatch mechanism cannot drive this today. |

Notes on omissions in the kernels: both are marked with `OMITTED VARIANT —
TODO(port)` header comments. `happyKernel` maps version<3→v2, ≥3→v3.
`warrenKernel` runs v1 for all version values (0→v1 fallback).

## 5. Divergence summary (per CallTree.md §4)

- **drift** (GATHER): conditional non-write becomes explicit copy-through
  `outTex.write(inTex.read(gid), gid)`. Global `Rand32` scan-order stream →
  per-thread integer hash of (gid, version); preserves gate probability
  `1/(1<<(bits-1))` but changes which cells are tested and does not animate
  without a frame uniform. Value uses `(self+1)&0xff` through standard NextR
  (source's `lc+1` produced a nonstandard middle byte; only `.b` is displayed).
- **happy v2/v3** (GATHER): direct NextR→packed-RGBA translation, no divergence.
  v2 = cardinal directional combine (GoDown/Up/Left/Right = 17/34/68/136);
  v3 = 8-neighbour one-bit-each OR. v1 omitted.
- **warren v1** (GATHER): write BYPASSES NextR — `.b`=r1, `.g`=0,
  `(.a<<8)+.r`=HiC=r2 (4-bit winner flag, NOT the counter). The "right" branch
  is ported literally, preserving the source's `if / if-else` control-flow quirk
  (Rule.cpp:800-802). Distance LUTs indexed by each diagonal neighbour's HiC low
  nibble (last frame's winner flag). v0 omitted.
- **noise** (SEQUENTIAL in source): raster run-length RNG replaced by an
  independent per-cell probability test `P(fire)=1/prob`, `prob=1<<noiseBits`
  (matching expected density, not per-frame-identical). Non-`.b` channels copied
  verbatim from input (source bypasses NextR on both branches). STATIC without a
  frame uniform — see §3.
